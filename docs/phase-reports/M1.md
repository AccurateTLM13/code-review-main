## 1. What shipped

| Task | Defect (reproduced on 0.2.2) | Fix | Design decision |
|---|---|---|---|
| **A21** | A registered token embedded in a *filename* reaches the model unredacted via `path` fields in `read_file` and `search_code` results (other routes were fixed in A19; these two were missed) | One serialization boundary for every model-facing tool result + opaque file handles | D1 |
| **A22** | `isLocalEndpoint` trusted `.local`, `.localhost`, `host.docker.internal`, `0.0.0.0` — none of which guarantee on-device traffic | Loopback-only trust (`localhost`, `127.0.0.0/8`, `::1`, `[::1]`) | D2 |
| **A23** | `search_code({isRegex:true})` compiled a model-authored `RegExp` on the main thread — catastrophic backtracking hung the process and defeated all budgets | Bounded worker execution: canary + host-side hard `terminate()` deadline; glob filters canary-checked with the same mechanism | D3 |

### A21 — one boundary for every model-facing tool result

**Code changes** (`src/engine/tools.mjs`, `src/evidence/validate.mjs`, `src/engine/prompts.mjs`):

1. **Single serialization gate.** New exported helper `emitToolResult({ name, payload, redactor })`: deep-redacts the payload (`redactDeep`) then fail-closed asserts via `assertNoRegisteredSecret(JSON.stringify(payload))` — a registered literal that survives serialization aborts the tool call. **Every** tool return goes through it: payloads *and* error objects. The error names a blocked secret only by its safe placeholder hash, never any literal material.
2. **Opaque file handles.** The toolkit maintains `state.handles` (rel → `f1`, `f2`, …) allocated lazily by every path-bearing tool. Each returned path field is accompanied by `handle`. `read_file`/`get_graph` accept `handle` (preferred) or `path`; `submit_findings` accepts a handle, a raw rel, **or the exact redacted path** a tool returned, and resolves it to the real rel (`draft.file` = redacted rel for every output surface, `draft._resolvedRel` = real rel, internal-only).
3. **Redacted-path resolution.** The toolkit eagerly builds a redacted→real map for the whole walked file set, so *any* redacted path the model sees (digest, graph lists, search hits) stays citable. `validateDrafts` resolves `_resolvedRel` first, then placeholder-shaped citations (`[REDACTED …`) back to the real rel — which also fixes the **structured phase**, where the context pack shows redacted paths (A19) that models quote verbatim; pre-fix such citations were falsely flagged "possible model invention".
4. **Prompts** updated: files are referenced by `handle` (`f1`, …); cite the handle (or the exact returned path) in `submit_findings.file`.

**Additive tool-result fields:** `handle` on path-bearing results, `coverage: 'full'|'partial'` on regex search results. No field was removed; report JSON schema unchanged.

### A22 — device-local means loopback

**Code change** (`src/util/model-access.mjs`): `isLocalEndpoint` now accepts only loopback literals — `localhost`, `127.0.0.0/8` (hostname starts `127.`), `::1`, `[::1]` (bare `::1` without brackets handled explicitly; unparseable input ⇒ remote). Removed from the trusted set: `*.local`, `*.localhost`, `host.docker.internal`, `0.0.0.0`, `localhost.localdomain`, bare hostnames, LAN IPs. No behavior change for model calls themselves — only the sensitive-file override trust decision (`allowSecretFileReads` ⇒ additionally requires `allowSecretFileReadsRemote` for anything non-loopback) and the derived `meta.models[].egress` labels.

### A23 — bounded regex searches

**Code changes** (new `src/util/regex-worker.mjs` + `src/util/regex-worker.impl.mjs`; `src/engine/tools.mjs` wiring):

- `runBoundedRegexSearch({ source, flags, files, deadlineMs, maxResults })` runs the pattern in a **worker thread** with every deadline enforced **host-side**: a canary job (worst-case strings `'a'.repeat(48)`, `'a'.repeat(48)+'b'`, a 48-char mixed string, 100 ms budget) rejects obvious pathologies before repository data is touched; the scan job runs under the remaining budget; expiry ⇒ `worker.terminate()` ⇒ `{ error: 'regex exceeded its time budget; simplify the pattern or use a plain substring search' }`. The wrapper never throws for pattern problems.
- Payload caps: 4,000 files / ~8 MB serialized — beyond that a prefix is scanned and `coverage: 'partial'` is reported honestly.
- `search_code` regex path uses the wrapper (`deadlineMs: 1200` — worst case ≪ the 2 s acceptance bound); **non-regex (literal) searches stay on the main thread** (no backtracking risk); budgets charge exactly as before.
- Model-authored **glob filters** also compile to RegExp — same class, so `list_files`/`search_code` globs are canary-checked with the same mechanism (`deadlineMs: 300`) and a pathological glob returns `glob filter exceeded its time budget; simplify the pattern (or drop the glob)`.
- Zero dependencies (decision D3): `worker_threads` + `terminate()` is a true wall-clock bound; RE2 was rejected to keep the package dependency-free.

## 6. Residual risk (stated honestly)

- **Redaction heuristics still cannot guarantee arbitrary-secret detection** (unchanged from 0.2.2): an *unrecognized* credential format in an ordinary-named file is not registered and not redacted; the A18 filename policy remains the real gate for credential-shaped files. M1 closes the *tool-result boundary* class, not arbitrary-secret detection.
- Under `--changed`, scope labeling matches findings against real changed paths; a finding on a file whose name contains a registered secret may be labeled `cross-file` instead of `changed` (conservative label; no exposure, no correctness loss).
- A repo file literally named `f1`/`f2`… would be shadowed by handle resolution *after* a handle with that id is allocated (handles are the documented preferred reference form; raw paths still resolve in all other cases).
- Worker-based regex requires `worker_threads` (Node ≥ 12) — guaranteed by `engines >=18.17`; if worker spawn fails, the wrapper degrades to an explicit `Regex search unavailable: …` error, never a hang.
- The canary is a heuristic screen: a pattern that passes the canary but explodes only on specific real data is still caught by the scan deadline (same budget error).
